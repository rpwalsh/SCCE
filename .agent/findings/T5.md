# T5 — graded non-Wikipedia benchmark (promise G6)

## The premise was already half-false, and the half that was true was worse than stated

G6 says the 293-item suite has 0 graded non-Wikipedia items. At HEAD it has 18: commit `cd2b507`
added a `loadHeterogeneous()` block to `tools/head-to-head/build-suite.mjs` in the same commit that
created this agent board, and `run.mjs` already grouped results `byWorkload`. The arithmetic
confirms the task text was written against the state just before that commit: the suite built in the
main checkout is 311 items, and 311 − 18 = 293.

So the honest finding is not "there are no non-wiki items". It is that the 18 that exist measure
less than they look like they do:

- **All 12 book items asked one question kind.** Every one was "name this entity" (who narrates,
  what is the ship called). None asked what happens at a named point, and none asked for a relation
  holding inside the narrative. All 6 code items asked the same question, literally: "Which file
  defines X?" — a filename lookup, not "what does this do" or "what depends on what".
- **Two items were passable by echoing the question.** The grader's fallback is
  `accepted.some(s => spoken.includes(normalize(s)))`, so gold that appears in the item's own prompt
  scores correct for an answer that repeats the question. `book:darcy` asked "Who is Mr Darcy?" for
  gold `["Darcy"]`; `book:frankenstein` asked "Who created the creature in Frankenstein?" for gold
  `["Victor", "Frankenstein"]`. Demonstrated with the real grader:

  ```
  book:darcy (old gold) -> answering with the question itself scores: correct
  book:frankenstein (old gold) -> answering with the question itself scores: correct
  book:darcy (new) -> answering with the question itself scores: wrong
  book:frankenstein (new) -> answering with the question itself scores: wrong
  ```

- **No item recorded what supported its answer.** The `source` field named the file the item was
  typed into, not the corpus document that answers it. A verdict could not be checked by hand.
- **6 of the 15 ingested novels were untested**, including two of the four largest.

## Suite format

`tools/head-to-head/` is the suite. `build-suite.mjs` assembles one manifest from the labelled sets
the repo already has; `run.mjs` asks each system and scores with `grade.mjs`; nothing else grades.

Item shape (`schema: scce.head_to_head_suite.v1`):

```json
{ "id": "book:moby-narrator", "workload": "book", "corpus": "gutenberg", "kind": "identity",
  "prompt": "Who narrates Moby-Dick?",
  "gold": { "requiredStrings": ["Ishmael"], "acceptedAnswers": ["Ishmael"],
            "forbiddenStrings": [], "unanswerable": false },
  "support": { "document": "corpus/gutenberg/moby-dick.txt", "quote": "CHAPTER 1. Loomings. Call me Ishmael." },
  "source": "tools/datasets/nonwiki-qa.json" }
```

Grading (`grade.mjs::score`), normalising to lowercase single-spaced:

- `forbiddenStrings` hit → `wrong`, before anything else.
- `requiredStrings` present → every whitespace/comma-separated part of every entry must be a
  substring of the answer. This is the strict path: `["Eloi", "Morlocks"]` demands both.
- Only when `requiredStrings` is empty does it fall back to `acceptedAnswers`, where **any one**
  entry being a substring scores `correct`.
- Otherwise `declined_when_answerable` if the answer matches the decline regex, else `wrong`.
- `gold.unanswerable` inverts: declining is `declined`, answering is `fabricated`.
- `gold.ungraded` (the 12 conversational probes) is never counted correct or wrong.

The lesson for authoring: put the discriminating token in `requiredStrings`, and never let it appear
in the prompt.

## Per-corpus reporting

`run.mjs` had its own private `summarize()` that grouped `byWorkload` only. Grouping now lives in
`grade.mjs` — the file that already owned "the verdict of an item must not depend on which harness
asked" — as `groupVerdicts`, `summarizeVerdicts` and `formatPerCorpus`. `run.mjs` spreads
`summarizeVerdicts` and prints with `formatPerCorpus`, so the offline check reads the exact bytes a
live run prints rather than a copy that can drift. Every item now carries `corpus`
(`wikipedia` | `gutenberg` | `code` | `none`), `build-suite.mjs` emits `gradedByCorpus`, and each
results row carries its corpus.

## Offline harness

`tools/head-to-head/suite-selfcheck.mjs` — no server, no database, no model. It fails if any item
lacks a corpus label, if the graded Gutenberg or code counts fall below 12 and 6, if the non-wiki
items collapse to fewer than 3 question kinds, if a non-wiki item lacks `support.document` /
`support.quote` or has no gold at all, or if **grading an item with its own prompt scores correct**
(hard failure for book and code items, warning for Wikipedia ones I do not own). It then replays five
canned answers through the real grader and asserts the per-corpus lines.


## Remaining uncertainty

- **Nothing here has been run against the live server.** The suite was not asked of SCCE; the
  per-corpus numbers above are a replay fixture proving the plumbing, not a capability measurement.
  I do not know what SCCE scores on these 36 items, and the items were chosen to be answerable from
  the corpus, not to be easy.
- Book URI duplication (up to 4 spellings of the same novel) is untouched. It inflates span counts
  and may affect retrieval ranking, but it does not affect whether a fact is present.
- `acceptedAnswers` substring matching stays generous: `closed-class-derived-from` accepts any of
  four tokens, so a partly-right answer can score correct. The strict `requiredStrings` path is used
  wherever a single discriminating token exists.
- The corpus stores code with tokenised spacing in some spans (`Kneser - Ney`, `⏎` for newlines), so
  multi-word code gold spanning punctuation is unreliable; every code item's gold is a single
  hyphenated identifier or a prose phrase from a doc comment.
- `book:pp-elizabeth-marries` rests on "talked of Mrs. Darcy" rather than a sentence stating the
  marriage outright — sound, but more indirect than the other eleven.
